================================================================================
ALGORITHM OVERVIEW
================================================================================

The new rule-based timetable generator works in 5 steps:

STEP 1: DATA FETCHING
├─ Retrieve all courses from database
├─ Filter by department and semester
├─ Retrieve all faculty members
├─ Filter by department
├─ Retrieve all available rooms
└─ Validate data exists

STEP 2: FACULTY-COURSE ASSIGNMENT
├─ For each course:
│  ├─ Search for faculty with matching specialization
│  ├─ If multiple match: pick least loaded
│  ├─ If no specialization match: assign first available
│  └─ Mark faculty as assigned to this course

STEP 3: SESSION SCHEDULING
├─ For each course, schedule required sessions:
│  ├─ For each day (Mon-Fri):
│  │  ├─ For each time slot:
│  │  │  ├─ Check if faculty available at this slot
│  │  │  ├─ Find available room for this slot
│  │  │  ├─ Check for conflicts (faculty/room double-booking)
│  │  │  ├─ If all OK: schedule the session
│  │  │  └─ If conflict: try next slot
│  │  └─ If insufficient sessions: relax constraints
│  └─ Continue until all sessions scheduled (or constraints relaxed)

STEP 4: ERROR HANDLING & FALLBACK
├─ If any error occurs:
│  ├─ Create fallback timetable with empty schedule
│  ├─ Save error details in conflicts array
│  └─ Return valid timetable object (NEVER throw exception)

STEP 5: SAVE & NOTIFY
├─ Save timetable to database
├─ Create success/error notification
└─ Return timetable object to frontend

================================================================================
CONFIGURATION
================================================================================

Hardcoded scheduling parameters:
- WEEKS: 13 (semester duration)
- DAYS: Monday-Friday (5 days)
- TIME_SLOTS: 6 slots per day (09:00-17:30)
- BREAK_SLOT: 12:15-13:15 (lunch, not scheduled)

Course scheduling:
- Default hoursPerWeek: 3
- Total sessions: 3 × 13 weeks = 39 hours per course
- Available slots: 5 days × 6 slots = 30 slots/week

Database expectations:
- Course.hoursPerWeek: Required for calculating sessions
- Faculty.specialization: Array of keywords for matching
- Faculty/Room.availability: Optional time slot constraints

================================================================================
ERROR HANDLING
================================================================================

Policy: NEVER fail completely - always return valid timetable

Progressive Fallback:
1. Try strict scheduling with all constraints
2. If insufficient sessions: relax availability constraints
3. If still insufficient: assign any available faculty/room
4. If critical error: return minimal timetable with error details
5. Result: Always valid timetable object (never throws exception)

Example error response:
{
  "_id": "...",
  "schedule": [],
  "conflicts": [{"type": "error", "message": "...error details..."}],
  "status": "draft",
  "metadata": {"totalHours": 0, "conflictCount": 1}
}

Timetable Generation:

├─ Input: {department, semester, academicYear, constraints}
├─ Output: Timetable object with full schedule
└─ Status: 201 Created

Other Timetable Endpoints:
GET    /api/timetables                  (list all)
GET    /api/timetables/:id              (get by ID)
PUT    /api/timetables/:id              (update)
DELETE /api/timetables/:id              (delete)

Supporting Endpoints:
GET/POST/PUT/DELETE /api/courses
GET/POST/PUT/DELETE /api/faculty
GET/POST/PUT/DELETE /api/rooms
